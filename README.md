# GitHub 插件下载器

适用于 Chrome / Edge 120 及以上版本。无需安装开发环境，无需构建，也不需要 GitHub 登录。

支持批量添加项目、手动更新、自定义自动检查周期、发布包选择、分支源码下载，以及配置导入和导出。

从 [Releases](https://github.com/RicardoSJin/github-extension-loader/releases) 下载插件 ZIP，或下载仓库源码后直接加载根目录。

## 安装

1. 解压发布的 ZIP，放到不会随意删除的位置。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 开启「开发者模式」，点击「加载已解压的扩展程序」。
4. 选择包含 `manifest.json` 的文件夹。
5. 点击工具栏中的本扩展图标，打开管理页面。
6. 点击「选择管理目录」，在系统“下载”中创建或选择 `GitHub插件` 文件夹并允许写入。此授权由浏览器要求，无法代替用户自动确认。
7. 添加或导入项目后点击「全部更新」。ZIP 会自动解压，每个项目直接放在 `GitHub插件/作者_项目/`，没有版本号或压缩包外层目录；选择含 `manifest.json` 的项目目录加载即可。

## 导入现成配置

仓库中的 [`examples/RicardoSJin-github-plugins.json`](examples/RicardoSJin-github-plugins.json) 包含 Bilibili Markdown 笔记、USTC 自动登录、ChatGPT Web Enhancer 和 DeepLearning.AI 助手四个公开项目。

下载该 JSON 后，在管理页面点击「导入配置」。默认每 24 小时检查并自动下载；DeepLearning.AI 助手没有 Releases 发布包，因此下载 main 分支源码，其中包含供 Tampermonkey 安装的油猴脚本。其他三个项目下载正式版发布包。

## 使用

- 粘贴多个完整 GitHub 项目地址，每行一个。点击「添加项目」，再点击「全部更新」。
- 优先下载 Releases 中的 ZIP / CRX / XPI。多个候选时展开「项目设置」，选择包名或填写规则，例如 `*chrome*.zip`。`*` 是唯一通配符；首次选择的精确包名若包含版本号，建议改成通配规则。
- 没有发布包时可切换「分支源码」。留空分支跟踪默认分支；源码并不一定可以直接安装，程序不会执行仓库中的构建脚本。
- 支持全局或独立周期（1 分钟至 365 天）。关闭「发现更新自动下载」后，只检查并显示可下载版本。浏览器的定时检查可能延迟，退出期间不执行，重启后补查。
- ZIP 自动解压到授权目录内固定的「作者_项目」文件夹，保留插件内部资源目录；后续版本写入同一目录。不会自动安装或重新加载浏览器扩展。CRX / XPI 仍作为文件下载，位于浏览器默认下载目录的设置子目录下。
- 「检查」仅查询版本；「下载新版」跳过已经成功解压的版本；「重新下载」重新解压并覆盖包内同名文件。文件被手动删除后，请使用「重新下载」。ZIP 内容通过 CRC 校验、路径校验，拒绝符号链接、加密包、重名或冲突路径；限制 5000 个文件、100 MB 解压大小。不支持 ZIP64。
- 更新后在浏览器扩展管理页点击“重新加载”。无根目录清单的源码或油猴脚本会明确提示不能直接作为扩展加载。
- 原 1.0.0 的下载目录不会自动删除或搬迁，以免破坏已加载扩展路径。升级后选择管理目录并点击“全部更新”，会重新下载解压到固定项目目录。
- 浏览器重启后可能要求重新授权目录，届时点击“选择管理目录”选择同一文件夹。目录授权不包含在导出配置中。
- 为保护本地文件，不删除旧版本中已移除的文件或自行添加的文件；失败时不会记为更新成功，但多文件写入不具备整体原子性，部分文件可能已经替换。重新下载可重试，完成前请勿重新加载扩展。
- GitHub 匿名接口有限流；程序自动延后重试。状态及任务保存在本机，下载成功后才提交版本记录；浏览器重启后会核对未完成的下载。
- 导出内容仅包含项目与设置。导入采用合并新项目方式，已有同名项目保留配置，全局设置由导入内容覆盖。不包含下载历史。

## 权限与数据

仅使用 storage（本地配置）、downloads（下载及状态）、alarms（定时检查）、api.github.com（公开项目元数据）。下载文件由浏览器从 GitHub 提供的地址获取。新增 GitHub 压缩包下载域名访问权限，用于读取并解压 ZIP；管理目录句柄仅存于本地 IndexedDB。无页面注入、无浏览记录读取、无统计服务；不向外部服务上传项目配置。

## 开发验证

使用原生 JavaScript 模块，无依赖、无需编译。运行 `npm test` 验证地址和路径处理、发布包匹配、下载状态、持久任务队列、重复下载、失败和限流。自动测试模拟浏览器 API，并非真实浏览器安装测试。

在 Windows PowerShell 中运行 `./package.ps1`，生成 `dist/github-extension-loader-v1.1.0.zip`。发布包只包含运行所需文件和说明，不包含测试或个人运行数据。

手动验收：添加一个有 Releases 的公开扩展仓库；检查并选择包；解压完成后确认项目目录直接包含 manifest.json；再次更新应跳过同版本；强制重新下载应保留副本；将周期设为 1 分钟，观察下一次检查时间；重启浏览器后确认设置与记录保留。
