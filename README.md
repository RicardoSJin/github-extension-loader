# GitHub 插件下载器

适用于 Chrome / Edge 120 及以上版本。无需安装开发环境，无需构建，也不需要 GitHub 登录。

支持一键发现并同步某个 GitHub 用户的全部插件、批量添加项目、批量更新进度、显示浏览器实际加载的版本并提示需要重新加载的扩展、自定义自动检查周期、发布包选择、分支源码下载，以及配置导入和导出。

从 [Releases](https://github.com/RicardoSJin/github-extension-loader/releases) 下载插件 ZIP，或下载仓库源码后直接加载根目录。

## 安装

1. 解压发布的 ZIP，放到不会随意删除的位置。也可以直接放进管理目录下的 `RicardoSJin_github-extension-loader/`，之后由下载器更新自己。
2. Chrome 打开 `chrome://extensions`；Edge 打开 `edge://extensions`。
3. 开启「开发者模式」，点击「加载已解压的扩展程序」。
4. 选择包含 `manifest.json` 的文件夹。
5. 点击工具栏中的本扩展图标，打开管理页面。
6. 点击「选择管理目录」，在系统“下载”中创建或选择存放插件的文件夹（例如 `GitHub插件`）并允许写入。此授权由浏览器要求，无法代替用户自动确认。
7. 在「一键同步全部插件」中检测并添加项目，或手动添加 / 导入项目后点击「全部更新」。ZIP 会自动解压，每个项目直接放在 `管理目录/作者_项目/`，没有版本号或压缩包外层目录；按「待加载」列表中的加载目录加载即可。

## 一键同步全部插件

输入 GitHub 用户名、组织名或主页地址（如 `RicardoSJin`），点击「检测插件」：

- 列出该用户的公开仓库，跳过派生仓库、已归档仓库和明显不是前端代码的仓库（如 Python、C），并在「已跳过」中说明原因。
- 在根目录或一级子目录（如 `extension/`）中找到带 `manifest_version` 的 `manifest.json` 即视为扩展；找到 `*.user.js` 视为油猴脚本，仅跟踪源码。
- 自动选择来源：有正式版发布包时跟踪正式版；只有预发布版本时勾选「包含预发布版本」；没有发布包时跟踪默认分支源码。包名规则由版本号替换为 `*` 生成，并排除 `source`、`firefox` 等其他构建，保证每次只匹配一个包。
- 结果以列表预览：新项目默认勾选；已在项目库且设置相同的灰显；设置不同的会列出差异，勾选后才覆盖（保留该项目的自动检查和周期设置）。确认后点击「添加 / 更新选中的项目」，可同时立即下载。
- GitHub 匿名额度为每小时 60 次。检测约消耗「1 + 扫描的仓库数 + 识别出的插件数」次请求，开始前会查询剩余额度（不计入额度）；中途被限流时返回已检测的部分，并在额度恢复后再试。

## 批量进度与待重新加载

- 「全部检查」「全部更新」和一键同步会显示批量进度：已完成数 / 总数、当前项目、每个项目的结果（已更新、已是最新、保留本地较新版本、失败原因等）和总用时。遇到限流时自动等待，不会把剩余项目记为失败。
- 解压出新文件的扩展会进入「待加载 / 待重新加载」列表，显示浏览器中的版本与目录中的版本。点击「打开扩展管理页」，对已加载的扩展点击“重新加载”，尚未加载的用“加载已解压的扩展程序”选择列表中的加载目录。浏览器加载新版本后会自动移出列表；也可以手动点击「我已重新加载」。
- 下载器更新自己后，列表中会出现「立即重新加载下载器」按钮；有任务进行时不可点击，避免中途重启。

## 浏览器已加载版本

项目卡片显示「浏览器已加载」：已是最新、未重新加载（目录中有新版本）、未加载、已停用，或有多个同名扩展。浏览器不提供已解压扩展的目录路径，因此按 manifest 中的名称匹配「已解压的扩展程序」，匹配到唯一一个后记住其扩展 ID；有多个同名扩展时可在「项目设置 → 对应的浏览器扩展」中手动指定。

此功能需要 `management` 权限，仅用于读取已安装扩展的名称、版本和启用状态，不会启用、停用、卸载或重新加载其他扩展。

## 页面版本与复制配置

页面标题旁显示实际加载的扩展版本，便于确认升级是否生效。如果后台服务仍在运行旧版本代码（常见于覆盖旧目录后首次加载），页面顶部会提示并提供「重新加载下载器」按钮。

点击「复制配置」即可将已保存的全局设置和项目配置复制为 JSON，可直接粘贴导入；与导出文件内容一致，不包含下载记录、目录授权或未保存的表单修改。浏览器拒绝剪贴板写入时会显示选中的文本供手动复制。

## 导入现成配置

仓库中的 [`examples/RicardoSJin-github-plugins.json`](examples/RicardoSJin-github-plugins.json) 包含作者的 7 个公开项目：GitHub 插件下载器本身、桥同步（预发布）、YouTube 新标签页（预发布）、Bilibili Markdown 笔记、USTC 自动登录、ChatGPT 网页增强，以及 DeepLearning.AI 助手（油猴脚本，跟踪 main 分支源码）。配置与「一键同步全部插件」的检测结果一致。

点击「导入文件」或「粘贴配置」打开导入窗口：

- 默认只加入新项目，已有项目保留原设置；勾选「同时更新已有项目的设置」后覆盖已有项目的来源和包名规则，下载记录保留，相同的包不会重新下载。
- 勾选「使用配置中的全局设置」才会用配置覆盖检查周期等全局设置；项目库为空时默认勾选。
- 导入前会完整校验，格式错误时显示原因，不会改动项目库。

## 使用

- 粘贴多个完整 GitHub 项目地址，每行一个。点击「添加项目」，再点击「全部更新」。
- 优先下载 Releases 中的 ZIP / CRX / XPI。多个候选时展开「项目设置」，选择包名或填写规则，例如 `*chrome*.zip`。`*` 是唯一通配符；首次选择的精确包名若包含版本号，建议改成通配规则。只有预发布版本的项目需要勾选「包含预发布版本」，否则会提示未找到正式版发布。
- 没有发布包时可切换「分支源码」。留空分支跟踪默认分支；源码并不一定可以直接安装，程序不会执行仓库中的构建脚本。
- 支持全局或独立周期（1 分钟至 365 天）。关闭「发现更新自动下载」后，只检查并显示可下载版本。浏览器的定时检查可能延迟，退出期间不执行，重启后补查。
- ZIP 自动解压到授权目录内固定的「作者_项目」文件夹，保留插件内部资源目录；后续版本写入同一目录。manifest 位于一级子目录（如源码中的 `extension/`）时，会提示加载该子目录。不会自动安装或重新加载浏览器扩展。CRX / XPI 仍作为文件下载，位于浏览器默认下载目录的设置子目录下。
- 「检查」仅查询版本；「下载新版」跳过已经成功解压的版本；「重新下载」重新解压并覆盖包内同名文件。文件被手动删除后，请使用「重新下载」。ZIP 内容通过 CRC 校验、路径校验，拒绝符号链接、加密包、重名或冲突路径；限制 5000 个文件、100 MB 解压大小。不支持 ZIP64。
- 不自动降级：目录中已有更高版本（例如本地开发版）时，不会被较旧的发布包覆盖，项目显示「保留本地较新版本」；确需回退时点击「重新下载」。
- 无根目录或一级子目录清单的源码、油猴脚本会明确提示不能直接作为扩展加载。
- 原 1.0.0 的下载目录不会自动删除或搬迁，以免破坏已加载扩展路径。升级后选择管理目录并点击“全部更新”，会重新下载解压到固定项目目录。
- 浏览器重启或下载器重新加载后，浏览器可能要求重新确认目录的写入权限。页面顶部会提示，点击「恢复目录授权」并在浏览器提示中允许即可，已解压的插件不会重新下载；因授权失效而失败的项目会自动重试。选择其他文件夹请点「更换目录」（选择同一文件夹同样不会重新下载）。目录授权不包含在导出配置中。
- 为保护本地文件，不删除旧版本中已移除的文件或自行添加的文件；失败时不会记为更新成功，但多文件写入不具备整体原子性，部分文件可能已经替换。重新下载可重试，完成前请勿重新加载扩展。
- GitHub 匿名接口有限流；程序自动延后重试，页面显示剩余额度。状态及任务保存在本机，下载成功后才提交版本记录；浏览器重启后会核对未完成的下载。
- 导出内容仅包含项目与设置，不包含下载历史、目录授权和对应的扩展 ID。

## 权限与数据

使用 storage（本地配置）、downloads（下载及状态）、alarms（定时检查）、management（只读：已安装扩展的名称、版本和启用状态）、api.github.com（公开项目元数据）。下载文件由浏览器从 GitHub 提供的地址获取。新增 GitHub 压缩包下载域名访问权限，用于读取并解压 ZIP；管理目录句柄仅存于本地 IndexedDB。无页面注入、无浏览记录读取、无统计服务；不向外部服务上传项目配置。通过商店等方式安装时，management 权限会显示“管理您的应用、扩展程序和主题”的提示；以“加载已解压的扩展程序”安装时不会弹出提示。

## 开发验证

使用原生 JavaScript 模块，无依赖、无需编译。运行 `npm test` 验证地址和路径处理、发布包匹配与一键检测规则（使用作者真实发布包名称）、子目录清单、下载状态、批量进度、持久任务队列、重复下载、不降级、目录授权恢复、导入选项、已加载版本匹配、失败和限流。自动测试模拟浏览器 API，并非真实浏览器安装测试。

打包：Windows PowerShell 运行 `./package.ps1`；macOS 运行 `mkdir -p dist && zip -X -j dist/github-extension-loader-v$(node -p "require('./manifest.json').version").zip manifest.json background.js core.js filesystem.js zip.js manager.html manager.js style.css README.md`。发布包只包含运行所需文件和说明，不包含测试或个人运行数据。

手动验收：在「一键同步全部插件」中检测一个用户，确认预览结果与跳过原因；添加并立即下载，观察批量进度；确认「待加载」列表与项目卡片的已加载版本；在扩展管理页加载或重新加载后列表自动清空；再次全部更新应全部为“已是最新”；重启浏览器后通过「恢复目录授权」恢复，确认没有重新下载。
